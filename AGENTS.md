# IsaacPerez.co — operating manual

Personal site at https://isaacperez.co: the homepage is a first-person, toy-eye-level 3D walk through Isaac's room. Visitors can explore the workstation, sneaker wall, bathroom and cat furniture; meet Mimi and Charlie; and open the same Me, Experience, My company and contact content as the editorial `/about/` page. `/about/` is the canonical source for that written content and retains the original `isaac.JPG` portrait, **Me → Experience → My company** order, and quiet personal contact footer. FIRSTUNIT branding appears only in the company content, with one company destination, `https://firstunit.io`. Keep the site free of an apps catalogue, pricing promotion, achievement engine and skills marquee.

Eight public pages are in the sitemap: `/`, `/about/`, `/photo/pricing/`, `/shootsort/`, `/roommate/{privacy,terms,support}/` (Quarters), and `/souvenir/privacy/` (Souvenir). `/room/` holds homepage runtime assets, not a separate page or sitemap URL. Pricing and ShootSort remain functional for existing visitors but are not promoted on the homepage. `/photo` and `/photo/` are permanent Vercel redirects to `https://firstunit.io/fu-0001` (currently HTTP 308); there is no `photo/index.html`. The retired capturedbyip.com domain redirects directly to that destination (HTTP 301, verified 2026-09-11). `404.html` handles unknown URLs.

Pure static — vanilla HTML/CSS/JS plus local GLB, image and video assets; no package.json, application build or CI. The WebGL room loads from `/room/`, while research, source photos, model-generation notes and the architecture atlas stay under repo-only `docs/`. Do not publish original room photos or source media merely to make the preview work: they include private details and may retain location metadata. `vercel.json` contains the photo redirects and response headers (hash-based CSP + HSTS + nosniff + frame/referrer/permissions/CORS), with no build command. `.vercelignore` keeps the repo-only files out of the deployment. Hosted on Vercel (project `isaacperez`, root `.`), auto-deploying `main` from GitHub `IsaacAPerez/IsaacPerez.co`. The project and team ids are in the Vercel dashboard — this is a public repo, so don't record them here.
Prime directive: the repo tree IS the site and a push to main IS a production deploy — keep it vanilla, and preview before you ship anything user-visible.

## Commands
- Rebuild the architecture atlas after changing how IsaacPerez.co works: `node docs/atlas/build.mjs` (edit `docs/atlas/data.mjs` only — `atlas.html` and `SYSTEM.md` are generated). It renders inside IsaacPerez.co's tab in the CodeByIP app, with a drift count since `data.mjs` was last committed; `docs/atlas/README.md` explains the set.
- Preview: `python3 -m http.server 8000` from repo root, open http://localhost:8000. No build step — any static server works.
- Deploy prod: `git push origin main` (Vercel auto-deploys; no CI, no staging gate).
- Manual deploy (avoid; ask first for prod): `vercel` (preview) / `vercel --prod` — CLI at `/opt/homebrew/bin/vercel`.
- Commit: `git commit -m 'type(scope): subject'` — types `feat|fix|chore|refactor|docs|test|perf|build|ci|revert`, enforced by hook (see Conventions).
- List public URLs that must stay in sync: `grep '<loc>' sitemap.xml` — that grep IS the list. `404.html` and the `/room/` asset directory are deliberately not in it.
- Check the repo before committing: `tools/check-site.sh` (repo-only, `.vercelignore`d, no dependencies). Six checks, each for a mistake this repo has actually made: every `src`/`href` resolves with the exact on-disk case (APFS hides a case slip that 404s on Vercel); no deployed page links a path `.vercelignore` withholds; `sitemap.xml` and the pages on disk agree both ways; every inline `<script>` body's sha256 is in `vercel.json`'s `script-src` and every declared hash is still used; and `/photo/pricing/`'s four prices agree across the JSON-LD, the cards and the meta description. `--remote` additionally status-checks the eight sitemap URLs and the ShootSort download (read-only `curl`, needs network). Exit status is the number of failures.

## Conventions
- Conventional Commits ENFORCED by the fleet hook: this repo's `core.hooksPath` → `/Users/isaacperez/Coding/platform/scripts/hooks`. `commit-msg` rejects anything not matching `type(scope): subject`. all but the most recent commit(s) predate the 2026-06-25 hook — do NOT imitate the old "Updated UI" log style. (added)
- Fleet hooks awareness: `post-commit` logs every commit to the CodeByIP dashboard feed (`~/Coding/CodeByIP/Backend/luka-log.py`, best-effort); `pre-commit` (Swift lint) no-ops here. No action needed for either. (added)
- Vanilla JS only: one IIFE per file with `'use strict'`. `room/*.js` owns the 3D homepage, `js/personal.js` owns the editorial `/about/` page, and `js/site.js` remains the shared utility-page behavior. Match the file you're in. The earlier office game, RPG stylesheet, unlinked fleet stylesheet and app catalogue icons were removed in the authorized dead-code audit; do not confuse them with the current `/room/` experience.
- Theme: the editorial `/about/` page and utility pages use `data-theme` on `<html>`, persisted to `localStorage['theme']`, with their inline pre-paint scripts in `<head>`. `js/personal.js` handles `/about/` and `js/site.js` handles utility pages. Both toggles have the same three-state `isDark()`, `aria-label`/`title` update, `prefers-color-scheme` listener and guarded storage write; both buttons ship `hidden` until their own script enables them. Change both implementations in the same commit when changing theme-toggle behavior. `js/site.js`'s `#navToggle` follows the same hidden-until-enabled rule. The room uses its own interactive music and lighting controls, not the editorial theme toggle.
- Mobbin is the design source of truth: before designing or redesigning any page or section, pull 2–3 real examples via the Mobbin MCP (`search_screens` for whole pages, `search_sections` for hero/pricing/footer-type sections; tool names may carry a server prefix — load via ToolSearch if deferred) with `platform: "web"`, `mode: "deep"` for nuanced queries, naming a top app to filter. Study the returned screenshot images — layout, hierarchy, spacing — not the metadata. Adapt the pattern, don't copy: colors and typography stay with this site's styles (`room/*.css` for the game, `css/personal.css` for `/about/`, `css/site.css` for utility pages). When presenting design directions to Isaac, cite each referenced screen as a markdown link to its `mobbin_url`.
- `prefers-reduced-motion`: gate room movement/animation and editorial reveals on the user's preference in `room/` and `js/personal.js`/`css/personal.css`. Shared `js/site.js` retains its existing `REDUCED` handling. Preserve a readable text path through `/about/` if 3D rendering is unavailable.
- Editorial `/about/` behavior: retain the portrait's 28px rounded mask. Fine-pointer hover adds a clipped portrait zoom; CSS handles link, arrow and theme transitions. `js/personal.js` uses IntersectionObserver and native Web Animations for one-time scroll reveals over always-visible baseline content. Honor live reduced-motion changes and reveal focused or hash-targeted content immediately; keep native anchor scrolling and add no motion dependency.
- Asset paths: root `index.html` and every subdirectory page use ABSOLUTE public paths (`/room/...`, `/css/...`, `/js/...`, `/favicon.svg`). This includes `/about/`, `/photo/pricing/`, `/shootsort/`, `/roommate/*/` and `/souvenir/*/`. `404.html` also uses absolute paths because it may be served for a bad URL at any depth. Match on-disk filename case exactly.
- The `/photo/pricing/` and `/shootsort/` navs link into editorial `/about/` in the same order: Me (`/about/#about`), Experience (`/about/#experience`), FIRSTUNIT (`/about/#firstunit`), plus Contact (`/about/#contact`). `#work` is a zero-size legacy anchor inside `/about/`'s Experience section; do not surface it as a nav item. The room homepage also handles old root fragments (`/#about`, `/#experience`, `/#work`, `/#firstunit`, `/#contact`) by opening the corresponding story content. Keep both utility navs byte-identical and their shared footer links in step; each block carries a SHARED marker naming the other page because there is no build step.
- CSS roles: `room/*.css` styles the first-person homepage. `css/personal.css` belongs to editorial `/about/`; `css/site.css` serves `/photo/pricing/`, `/shootsort/` and `404.html`; keep it unchanged when implementing a room or editorial variation. `css/photo.css` serves `/photo/pricing/` only. `css/legal.css` serves the four legal-style pages, carrying their shared `.legal-*` layout; put rules shared by all four there, while page-only extras stay page-scoped (only `/souvenir/privacy/` currently has a small page-specific block). The retired `css/game.css`, `css/rpg.css`, `js/game.js`, unlinked design-system stylesheet and app-icon catalogue are absent from this repo; the current game is under `/room/`.
- A one-off page (`/shootsort/`, `404.html`) carries its handful of extra rules in a page-scoped `<style>` block rather than widening a shared stylesheet's role. Among the legal-style pages only `/souvenir/privacy/` still has one, for the table/`<pre>`/`hr`/`code`/`h3` rules it alone needs: a rule that all four of a stylesheet's only consumers carry belongs in that stylesheet, and one page's extras do not. (added)
- Contact destinations are split by intent: `/about/`'s personal footer and the room's story/contact panel use `iperez2435@gmail.com`; the Quarters/Souvenir legal pages carry the same personal address. Every commercial CTA on `/photo/pricing/` mails `hello@firstunit.io` — the enquiries address FIRSTUNIT itself publishes (`~/Coding/firstunit-brand/brand.json`, and firstunit.io/fu-0001, the practice this page prices). Keep the `?subject=Quote request: <package>` prefill; a quote CTA must never land on the personal contact address.
- The FIRSTUNIT wordmark appears twice — `/about/index.html` `.company-wordmark` and `/photo/pricing/` `.fu-wordmark` — and both are byte-identical to `~/Coding/firstunit-brand/assets/wordmark/fu-0001-wordmark-interim.svg`. If the brand repo re-cuts the mark, replace BOTH in the same commit. `FU—0001` takes an em dash in display, `fu-0001` in the URL (BRAND.md §"The cut").
- Content that has a canonical source in ANOTHER repo is rendered here, not authored here: `/souvenir/privacy/` is a rendering of `~/Coding/Souvenir/docs/privacy.md`. Edit the source, then re-render. `/roommate/support/` deliberately summarises and links to `thequarters.app/support` (the App Store support URL, generated from `~/Coding/RoommateApp/legal/SUPPORT.md`) instead of forking that FAQ.
- `localStorage`: runtime reads and writes in `js/personal.js` and `js/site.js` are wrapped in try/catch (Safari private mode). The inline pre-paint theme scripts in those pages' `<head>` call `getItem` bare — leave them as-is. `theme` is the editorial/utility preference; any old `ip-achievements` or `ip-game-state` values are dormant and should not be cleared as homepage cleanup.
- Every public page carries a canonical `<link>` to its exact `https://isaacperez.co/...` URL; `sitemap.xml` is updated in the same commit as any page add/remove — and in the same commit as any edit to what a page RENDERS, because each `<url>` carries a `<lastmod>`. Bump only the page whose body changed: a head-only edit (og tags, theme-color, an icon href) is not a content change, and a lastmod that moves on every deploy is one Google learns to ignore, which is worse than none. No `<changefreq>` or `<priority>` — both are ignored, and a field nobody reads goes stale unnoticed. `--` is illegal inside an XML comment, so the file's own note uses em dashes. (added)

Change the SVG and re-render both from it. `/about/`, `/shootsort/`, `/photo/pricing/` and `404.html` pair light/dark theme-color values with their real backgrounds (#fbfbfd / #000000); the room homepage uses its own single light `#fbfbfd` theme-color; the four legal pages use #ffffff / #1d1d1f.

Keep prices off the cached pricing card.
- Small site images are optimized IN PLACE before committing under the same filename: icons ≤ ~105KB, editorial photos ≤ ~200KB. A raster is exported at ~3× the box it renders in: `tinderLogo.png` 71×84 for a 24×28 box, `berkeley-seal.png` 96×96 for 32×32, `ndLogo.webp` 160×160 for the 44×44 box `.employer-icon-nextdoor` then scaled by 1.22. - `.gitignore` is one line (`.vercel`). Zero secrets or `.env` files, no external API calls — the fleet's 1Password setup has nothing to wire up here; keep it that way. Same-origin `fetch` for `/about/` content and `/room/` assets does not require a service key.
- `.vercelignore` is the line between "in the repo" and "on the internet". Every tracked file is served at `https://isaacperez.co/<path>` unless listed there: `AGENTS.md`, `CLAUDE.md`, `docs/`, `Resume.pdf`, `fonts/jetbrains-mono-latin.woff2`, `tools/`, `brand/` and `scripts/brand-studio.sh` are repo-only. `/room/` is intentionally public and must contain only curated runtime assets; never copy the original room or cat photos into it without a privacy/metadata review. Add any new unpublished doc, note or asset to `.vercelignore` in the same commit. `vercel.json` also adds `X-Robots-Tag: noindex, nofollow` for `/docs/(.*)`, `/AGENTS.md` and `/CLAUDE.md`; this is a fallback, not a substitute for excluding the files.

## Mistakes you will make here
- **Wrong filename case that works locally and 404s in prod.** macOS APFS is case-insensitive; Vercel is not — the `/about/` portrait really is `isaac.JPG` (uppercase). Reference every asset with its exact on-disk case; run `tools/check-site.sh` before committing, which compares references against directory entries literally.
- **Committing unoptimized images or private source photos.** Keep editorial icons/photos within their existing budgets and review the total `/room/` runtime payload. Original room and cat reference photos may carry location metadata and personal details. Keep them repo-only under `docs/` or outside the repository, never in public `/room/`.
- **Copying asset paths between page types.** Relative `css/...` paths pasted into `/about/` or `/roommate/x/` can break deployed. Every public page here now uses absolute `/css/...`, `/js/...` or `/room/...` paths, including root `index.html` and `404.html`.
- **"Tidying" the editorial inline theme script into external JS.** The pre-paint IIFE in `/about/index.html` `<head>` prevents a flash of the wrong theme. Keep it inline before the stylesheet; do not externalize or defer it. The 3D root homepage has no pre-paint theme IIFE.
- **Editing an inline `<script>` without recomputing its CSP hash.** `script-src` in `vercel.json` has no `'unsafe-inline'`; hashes cover the pre-paint theme IIFEs (`/about/`, `404.html`, `/shootsort/`, `/photo/pricing/` and legal pages) and JSON-LD blocks (`/about/`'s Person graph and `/photo/pricing/`'s OfferCatalog). The hashes are byte-exact: changing indentation can make the browser refuse the block. After touching an inline `<script>`, regenerate its hash (`printf '%s' "$body" | openssl dgst -sha256 -binary | openssl base64`, where `$body` is the verbatim text between the tags) and update `vercel.json` in the same commit. `tools/check-site.sh` reports both missing and orphaned hashes. CSP also refuses injected headless-Chrome scripts; drive tools such as axe through debugger-world evaluation with CSP bypass rather than mistaking blocked injection for a clean result.
- **Adding tooling to "fix" the missing build/CI.** No package.json, no `.github/`, no runner for this repo — by design; Vercel git integration is the entire pipeline. Rule: never add package.json, bundlers, frameworks, node_modules, or workflows.
- **Imitating the git log's commit style.** Almost all history predates the commit-msg hook and would be rejected today. Rule: write `fix(game): ...` / `feat(site): ...` regardless of what `git log` shows; no `--no-verify`.
- **New animation that ignores reduced motion.** Branch room animation, camera movement and editorial reveals on the motion preference or a `prefers-reduced-motion` media query; keep content readable and navigable through `/about/`.

## Quality bar
Room homepage edit (`index.html` / `room/`):
- Loads through a local static server with the production CSP headers replayed and zero console errors. Verify actual WebGL rendering, movement, camera modes, at least one inspectable story, Mimi/Charlie interaction, and the direct `/about/` text path.
- Keep the user-approved room proportions: the 70-inch desk and queen bed are scale anchors; the sneaker wall, bathroom approach, desk-mounted monitor, cat wall and corner box remain coherent. Keep the bathroom entrance unobstructed.
- Story panels and the desk monitor derive biography, experience, company and contact from `/about/` rather than maintaining a second copy. Keep old root fragment links (`/#about`, `/#experience`, `/#work`, `/#firstunit`, `/#contact`) useful.
- Check keyboard, mouse and small-screen touch navigation, reduced-motion behavior, accessible controls, music and light controls, and a no-WebGL route to `/about/`. Do not publish original source photos, EXIF location metadata or private reference galleries.
- Verify exact-case asset paths, total public payload and loading on a mobile viewport. No new third-party scripts, build tooling or external API dependencies.
- Shared utility-page assets, all eight sitemap routes and the photo redirects remain functional. Commit passes the hook without `--no-verify`.

Editorial page edit (`/about/index.html` / `css/personal.css` / `js/personal.js`):
- Renders with zero console errors. **Me → Experience → My company** stays the content order; the original portrait remains in Me and personal contact stays in the footer.
- FIRSTUNIT branding stays inside the company section, with one company destination (`https://firstunit.io`). Do not add an apps catalogue, photography/pricing promotion, achievement engine or skills marquee.
- Its inline theme pre-paint script remains verbatim in `<head>` unless its CSP hash is changed in the same commit. Preserve native anchors, reduced-motion handling and compatibility with utility-page links.
- `js/site.js` is not a dependency of either the room homepage or `/about/`; exact-case asset references and canonical URLs still pass `tools/check-site.sh`.

New public page (e.g. legal page for a fleet iOS app):
- Lives at `<app>/<page>/index.html` (extensionless URL with trailing slash).
- Absolute asset paths (`/css/legal.css` pattern).
- Canonical `<link>` to its exact `https://isaacperez.co/<path>/` URL.
- `sitemap.xml` gains the `<loc>` entry in the same commit; existing URLs untouched.

Image/asset update:
- Size within budget vs existing root image files.
- Replaced in place under the same filename, OR every reference updated with exact case.
- If the `/about/` portrait changed, re-export `isaac.avif` and `isaac.JPG` from the same source. If a share image changed, verify its `og:image`/`twitter:image`, dimensions and alt text on its own page.

Deploy:
- `git push origin main`, then verify the deployed room homepage and `/about/` separately (browser or `curl`), plus the eight sitemap routes and photo redirects. A successful push alone is not a rendered-site check.
- `git status` shows no `.vercel/` contents, secrets, or `.env` staged.
